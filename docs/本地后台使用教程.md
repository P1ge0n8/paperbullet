# 锵稿新版后台：VS Code 本地编辑与发布教程

适用版本：连续正文编辑器，2026年11月26日更新。

工作流程：**本地编辑 → 本地预览 → 保存并提交 → 手动发布 → 检查正式网站。**

本项目采用「新版后台同步到 GitHub，VS Code 启动本地编辑，再发布正式网站」的方式。后台代码与网站代码放在同一个仓库；后台在你的电脑上运行，读者访问的是 GitHub Pages 上的正式网站。关闭电脑不会影响已经上线的网站。后台账号只用于本机编辑，GitHub 登录用于同步项目与发布，两者分别管理。

- [正式网站](https://p1ge0n8.github.io/paperbullet/)
- [GitHub 仓库](https://github.com/P1ge0n8/paperbullet)
- [发布进度](https://github.com/P1ge0n8/paperbullet/actions)

浏览器里编辑并点击「保存全部修改」后，VS Code 的「源代码管理」会直接出现对应文件的变化，无需另行导出文章或复制粘贴。浏览器、VS Code 和发布脚本使用同一份项目。

## 1. 打开正确的项目

这台电脑的正式源码目录：

```text
/Users/yinzibin/Documents/Codex/2026-09-27/product-design-plugin-product-design-openai-9/outputs/paperbullet
```

在 VS Code 选择「文件 → 打开工作区文件」，打开该目录里的 `PAPERBULLET.code-workspace`，也可以直接打开整个 `paperbullet` 文件夹。

日常编辑使用正式源码目录。聊天工作目录里的 `work/qian-site`、`outputs/锵稿放映室` 是镜像或预览副本；此前的 `8942` 地址不是后台地址。

在新电脑上继续时：

```sh
git clone https://github.com/P1ge0n8/paperbullet.git
cd paperbullet
npm ci
```

然后打开新克隆项目的 `PAPERBULLET.code-workspace`。如果终端已安装 VS Code 的 `code` 命令，也可运行 `code PAPERBULLET.code-workspace`；未安装时使用 VS Code 菜单打开即可。新电脑需要设置自己的本机管理员账号。

确认左侧项目名称是「锵稿 · PAPERBULLET」，其中包含 `admin`、`content`、`src`、`public`。不要只打开 `dist`、下载出的单个网页或另一个旧预览文件夹。新版文章正文应是一块连续编辑区；如果仍是一段一个输入框，先确认项目目录，再重新启动后台并刷新网页。

## 2. 第一次准备

需要 Git、VS Code、Node.js 22.12 或更高版本。在 VS Code「终端 → 新建终端」执行：

```sh
node --version
npm --version
git --version
npm ci
```

前三行查看工具是否可用；`npm ci` 按锁定版本安装依赖。普通内容编辑无需每次重新安装。发布前还需在 VS Code 或 Git 中完成 GitHub 登录，并拥有 `P1ge0n8/paperbullet` 的推送权限。

## 3. 从 VS Code 启动

按 `⌘⇧P` 打开命令面板，选择「运行任务」或 `Tasks: Run Task`，再选择 **锵稿：启动本地后台**。

等效命令：

```sh
npm run admin
```

终端出现地址后打开：

- 后台：http://127.0.0.1:4181/admin/
- 本地网站：http://127.0.0.1:4181/
- 直接进入内容：http://127.0.0.1:4181/#/about

编辑期间保留终端运行。停止时在对应终端按 `Control+C`，或在 VS Code 终止任务。

首次在尚未设置账号的电脑打开后台，或已主动重置登录设置时，会显示「设置你的后台」。账号至少 2 个字符，密码至少 12 个字符，请自行设置并妥善保存。已有账号时登录原账号。正常更新代码不会重置账号；后台重启后，需要重新登录。

只看网站时，可运行任务 **锵稿：只预览前台** 或 `npm run dev`，打开终端显示的地址；它与后台是不同服务。

### VS Code 日常任务速查

| 想做什么 | 在「运行任务」中选择 | 对应命令 |
| --- | --- | --- |
| 写文章、整理播客与分类 | 锵稿：启动本地后台 | `npm run admin` |
| 只查看网站 | 锵稿：只预览前台 | `npm run dev` |
| 检查能否发布 | 锵稿：发布前检查 | `npm run check` |
| 发布已提交版本 | 锵稿：手动发布到 GitHub | `npm run publish:github` |

文章、图片在浏览器里编辑；文件变化、版本记录与发布在 VS Code 里处理。完成后先保存文章，再停止运行后台的终端。修改了后台代码或安装了依赖时，也应先保存、停止、重新启动后台，最后刷新浏览器。

## 4. 保存、公开和上线的区别

| 操作 | 作用 | 正式网站立即改变吗 |
| --- | --- | --- |
| 在后台编辑文字、图片或设置 | 修改暂存在当前页面 | 不会 |
| 保存全部修改 | 写入本机项目，生成公开数据 | 不会 |
| 状态选草稿 | 只留在后台，不进入网站列表 | 不会 |
| 状态选公开并保存 | 进入本地前台与下一次构建 | 不会 |
| VS Code 提交 | 为本地修改建立版本 | 不会 |
| 手动发布到 GitHub | 推送已提交版本并触发部署 | 部署成功后更新 |

发布时间只是显示日期，不是定时发布开关。状态为公开的内容，无论填什么日期，都在保存后进入本地前台，并随下一次发布上线。

## 5. 管理栏目分类

进入 **栏目分类**，可以新建、修改、排序：

- **专栏作者**：子戈、徐元、梅雪风等作者专栏。
- **影展专题**：戛纳、威尼斯、柏林等影展集合。

可编辑栏目名称、类型、英文名称和介绍。已有栏目有固定网址标识；改显示名称不会自动改链接，请不要随意修改原有 `id`。

文章设置里的「网站栏目」用于选择影评、看片指南、影坛观察、影展专题、深度访谈或商业合作；「所属栏目」用于原有作者专栏或影展集合。「文章分类」则是展示在卡片上的分类文字，三者用途不同。

已有文章的栏目不能直接删除或改变类型。先到文章编辑里更改「所属栏目」，迁移所有关联文章后再操作。新建影展不会凭空生成官方标志，页面使用名称入口；已有影展保留原标志。

## 6. 编辑文章

进入 **文章**，点击「＋ 新建」或从左侧选择文章。

### 基本信息

| 字段 | 用途 |
| --- | --- |
| 主标题 | 文章页大标题，也用于文章列表 |
| 副标题／摘要 | 主标题下的说明与列表摘要 |
| 文章编号 | 例如 `006`，保留前导零；与排列顺序独立 |
| 所属栏目 | 决定文章出现在哪个作者专栏或影展 |
| 文章分类 | 卡片分类文字，例如「戛纳专栏」「影评」 |
| 作者 | 正式署名 |
| 发布时间 | 按填写的本地日期、时间显示 |
| 状态 | 草稿或公开；公开前须有作者、日期、正文 |

主标题、副标题保留在正文之外，便于分别管理标题与内容。展开标题排版设置，可分别设置字号、粗体、斜体、左／中／右对齐；清空字号使用网站默认值，「恢复默认」还原该部分的排版。字体沿用网站既有字体系统。作者、栏目、状态和编号放在可展开的「文章设置」里；发布时间与文章封面在「日期与封面」里单独管理。

### 序言（开腔）

展开「序言（开腔）」即可编辑序言。序言与正文各有一个连续编辑区，直接点击文字就能修改，不再按每段填写表单。没有序言时留空即可；第一段设为二级或三级标题时，阅读页使用该标题，否则显示「开腔」。署名、配图也可写在序言中。

原稿里的封面或转载说明可以放在「序言前的内容」。用「序言前保留的正文段数」调整位置，再点「预览排版」核对顺序。编辑前置内容时，其后的序言和正文仍保持原有顺序。切换编辑语言可以单独修改该语言的序言。

### 连续编辑正文

点击正文即可开始写作，也可以一次粘贴整篇文章的文字。图片通过图片库插入；从其他网页或文档复制来的图片，请先保存为图片文件再上传。

| 操作 | 方法 |
| --- | --- |
| 新建一段 | 按 `Enter` |
| 同一段内换行 | 按 `Shift+Enter` |
| 合并两段 | 在后一段开头按 `Backspace` |
| 调整几字的格式 | 先选中文字，再点粗体、斜体或设置字号；字号按 `Enter` 或点击其他位置生效 |
| 设置小标题、引用 | 将光标放在该段，使用工具栏的「段落样式」 |
| 调整段落对齐 | 将光标放在该段，或选中多段，再选左／中／右对齐 |
| 添加文字链接 | 选中文字，点击「设置链接」，在工具栏下填写完整地址，再点「应用」 |
| 撤销／重做 | 使用工具栏按钮，或 Mac 的 `⌘Z`／`⌘⇧Z`；Windows 使用 `Ctrl+Z`／`Ctrl+Shift+Z` |

正文工具栏作用于当前选区或所在段落。局部粗体、斜体、字号、链接不再要求拆出一个新段落；二／三级标题仍会进入文章内目录。字号范围为 14–48px。需要恢复文字样式时，先选中文字，再使用「清除文字格式」。

编辑已有链接时，将光标放在链接文字内，再点「设置链接」修改地址，或点「移除链接」取消跳转。链接填写完整的 `https://…` 或 `http://…` 地址。粘贴会按编辑器支持的格式整理为文字、标题、引用等内容；复杂表格、网页布局或外部字体不保证原样保留，请用「预览排版」核对。已有文章、编号、图片和图内文字可以继续编辑，不必重新录入。

### 在正文中插入和调整图片

将光标放在需要插图的位置，点击工具栏的「插入图片」，选择图片库中的图片或上传新图片。图片直接出现在正文中；点击图片后，使用工具栏下出现的图片设置调整尺寸和图注；展开「图片描述与图内文字」可以补充描述与转录。

- 宽度：20%～100%，相对于所在阅读栏。
- 高度上限：120～1200px；留空使用网站默认值。
- 对齐：左、居中、右。
- 「恢复默认尺寸」：清除手动宽度和高度，恢复网站默认尺度。
- 图片描述：说明图片内容。
- 图注：显示在图片下方。
- 图内文字：保留已有转录，也可补充校对，读者可展开查看。

图片保持原比例，尺寸控制不会裁掉原图。较窄宽度适合竖版海报，较宽适合横向剧照。可在图片设置中点击「替换图片」或「删除图片」；删除正文引用不会删除图片库文件。

文章封面仍在「日期与封面」里单独选择、移除和调整，不与正文插图混为同一张。

### 预览与保存

点击「预览排版」可查看当前未保存内容或草稿，点击「继续编辑」返回编辑区。这里不会自动保存；完成一轮编辑后，点击 **保存全部修改**。公开文章保存后，可通过「前台查看 ↗」打开真实本地文章页。

撤销／重做用于当前编辑区的文字与图片操作，不等于恢复整个项目的历史版本。切换文章、语言或预览后，不要依赖之前编辑区的撤销记录；重要修改应及时保存。

关闭页面前先保存。如果出现内容冲突提示，说明另一窗口或 VS Code 改过同一份数据。先复制保留当前未保存文字，再重新载入并合并。

## 7. 更新播客

进入 **播客**：

1. 新建或选择已有单集。
2. 选择节目归属：过度解读／保留意见。
3. 填写单集标题、封面和完整跳转链接，优先使用该单集的 `/episode/…` 地址。
4. 设置发布时间、时长、附加标记；例如「57分钟」「试听」，也可留空可选项。
5. 选择草稿或公开，用上移／下移调整顺序。
6. 保存，再到本地播客页分别检查两个节目。

节目归属决定单集放在哪一组。只改封面不会自动移动节目。后台不会自动抓取小宇宙的新节目；平台发布单集后，需要手动录入信息再上线。

## 8. 简体、繁体与英文内容

网站提供简体中文、繁体中文和英文显示。后台的语言编辑选项用于维护不同语言版本；切换编辑语言并填写该语言的标题、摘要、正文或节目标题，再保存。

文章、播客和栏目分类都可以切换「编辑语言」。尚无译文时，先点「建立译文」；系统复制原稿作为编辑起点，需要你填写译文，不会自动翻译。删除某个语言的译文后，该语言回退显示原文。栏目名称与说明也应同步维护，避免更名后另一语言仍显示旧名称。

已提供的译文可直接继续编辑，来源说明见 [译文来源说明](译文来源说明.md)。新增或导入文章需要分别检查是否已有译文；缺失时网站回退显示原文。前台选项简写为「繁體中文」，实际语言设置仍为香港繁体。

前台切换语言时先淡出当前内容，再淡入新语言，并保留所在页面。英文版栏目标题上方仅显示居中的 01–06 编号；影展标志下不重复显示英文名称。中文版本保留完整栏目标签与影展名称。

各语言的正文、序言、段落结构、局部格式、插图与图注独立保存。中文新增、删除、合并段落或调整图片，不会连带改动已有繁体、英文正文；需要时分别切换语言更新。这样可以根据译文长度调整分段，也避免按段落序号误删译文。

文章分类归属、编号、状态、发布时间、封面和主／副标题排版仍共用。播客翻译只改变显示文案，不改变原始节目音频和跳转地址。

修改中文原稿后，需要同步检查繁体、英文版本；已有译文不会因为中文修改而自动重新翻译。三种语言都应在本地前台检查后再发布。

## 9. 图片库

进入 **图片库** 上传 PNG、JPG、WebP、GIF，单张最大 10 MB。文件保存在 `public/uploads/`，上传后还要在文章或播客里选用。

为避免误删引用中的图片，后台不直接提供删除图片文件的按钮。确定无引用后，可在 VS Code 删除对应文件。发布时新图片必须一并提交，只提交文字数据会导致线上图片缺失。

## 10. 每次上线的完整步骤

### A. 本地编辑与检查

先确认 VS Code 打开的是这次实际运行后台的项目；多份副本不会自动互相同步。

1. 编辑并点击「保存全部修改」。
2. 打开本地网站检查文章、图片、链接、三种语言和手机宽度。
3. 运行任务 **锵稿：发布前检查**，或：

```sh
npm run check
```

该命令会生成公开内容并构建网站，另外编译本地编辑器，运行内容、后台、编辑器与站点测试。测试通过不代表已经上线；失败时先处理终端提示。

### B. 在 VS Code 提交

打开左侧「源代码管理」，查看本次修改，通常包括：

```text
content/editorial.json
src/content/published.json
public/archive-articles/发生变化的文章数据.json
public/uploads/新图片
```

`content/editorial.json` 是编辑源；其余公开文章数据由保存或构建生成。源文件与本次变化的生成文件一起提交，图片也要提交。不要只提交 `published.json`，否则下次构建会用旧编辑源重新生成。

网页代码、教程和其他本次确实需要发布的文件也一起检查。点击文件旁「＋」暂存，填写说明，例如「更新戛纳专栏 006，新增保留意见单集」，再点击「提交」。

不要提交 `.local-admin/`、`node_modules/`、`studio/node_modules`、`dist/`、`.env` 或个人临时文件。项目已有忽略规则，不要强制加入。

### C. 手动发布

运行任务 **锵稿：手动发布到 GitHub**，或：

```sh
npm run publish:github
```

脚本会确认分支为 `main`、目标仓库正确、已跟踪文件都已提交，再获取 GitHub 状态、运行检查、列出待发布提交。核对后在终端输入 **发布**，才会推送；输入其他内容取消。

发布任务推送的是已经提交的版本，不会把浏览器里尚未保存的内容带上，也不会自动暂存、提交或强制覆盖远端。发布期间继续保存的新修改，需要再次检查、提交后才能随下一次发布上线。未跟踪文件只列出文件名，不自动加入。如果新图片或代码需要上线，先取消，在 VS Code 暂存并提交，再重新发布。检查生成了新修改时也需先提交。

熟悉 Git 后，可以手动执行以下流程，但仍需先在 VS Code 提交：

```sh
npm run check
git status
git push origin main
```

### D. 确认部署成功

推送成功只表示仓库已更新。打开 [GitHub Actions](https://github.com/P1ge0n8/paperbullet/actions)，找到对应提交的 **Publish PAPERBULLET**，等待部署成功，再检查[正式网站](https://p1ge0n8.github.io/paperbullet/)。旧页面可能需要强制刷新或新标签页。

GitHub 保存可运行的新版后台源码，GitHub Pages 发布供读者访问的网站。正式网站的 `/admin/` 不是管理入口；日常后台地址仍是你电脑上的 `4181/admin/`。换电脑时先获取仓库、安装依赖，再启动后台。

### E. 从 GitHub 更新本地项目

在另一台电脑或其他工作区修改过项目后，先同步，再开始新一轮编辑：

1. 在后台点击「保存全部修改」。不要在仍有未保存文字的浏览器页面直接拉取代码。
2. 在 VS Code 查看「源代码管理」。有本地修改时，先检查并提交文章、图片和相关代码，建立本地版本；此时无需推送。不要使用「放弃所有更改」。
3. 停止后台，在项目终端执行：

```sh
git status --short
git fetch origin main
git status -sb
git pull --ff-only origin main
```

`git status --short` 应没有需要保留却未提交的文件。最后一行只接受可以直接向前更新的情况，避免自动覆盖或混合两份内容。若提示无法快进，表示本地和 GitHub 都有新提交，需要先合并，见下方「两边都有修改」。

4. 更新成功后运行：

```sh
npm ci
npm run check
npm run admin
```

5. 刷新后台并登录，确认文章与最新代码都已加载，再开始编辑。不要继续使用拉取前的旧编辑页面。

#### 两边都有修改

先保留已提交的本地版本，再在 VS Code 的合并编辑器中处理 `git merge origin/main` 产生的差异。文章源数据发生冲突时，逐项核对两边需要保留的文章，不要直接把整份 `content/editorial.json` 接受为「当前」或「传入」而丢掉另一边内容。

合并编辑源后运行 `npm run content:publish`，重新生成公开数据，再运行 `npm run check`。检查文章、图片与译文后提交合并结果，再执行发布任务。不要用强制推送或 `reset --hard` 解决内容冲突。

建议一个时间段只在一个项目副本里编辑。VS Code 的「同步更改」可能同时拉取和推送；需要明确控制上线时，使用本教程的获取、合并、提交和发布步骤。

## 11. 常见问题与回退

### 端口被占用

通常后台已经运行，先打开 `4181/admin/`。需要另用端口时，在 macOS 终端执行：

```sh
ADMIN_PORT=4182 npm run admin
```

之后使用终端显示的新地址。测试使用独立端口 `4197` 和临时目录，不修改真实账号或文章。

### 浏览器保存后，VS Code 没有变化

先确认页面提示「已保存到本地」，再确认 VS Code 打开的是运行后台的同一项目。重新保存完全相同的内容不会产生新的文件变化。若 VS Code 正打开旧的源数据文件，先重新读取磁盘内容，再编辑，避免把旧内容覆盖回去。

### 保存后网站还是旧内容

先分清本地 `4181` 和正式网站。保存只更新本机；正式网站需要提交、发布和 Actions 成功。再检查条目是否为草稿，以及栏目／节目归属是否正确。

### 推送被拒绝

检查 GitHub 登录与权限。如果 GitHub 比本地多出提交，在 VS Code 拉取、解决冲突，再检查、提交、发布。不要使用强制推送覆盖他人版本。

### 忘记密码或换电脑

本机账号资料保存在 `.local-admin/account.json`，已被 Git 忽略。忘记密码时先停止后台，把该文件移到项目外备份，再启动后台设置新账号，不要删除文章或图片。新电脑重新设置本机账号。重启后台后需要重新登录。

### 撤回已经上线的版本

用反向提交保留历史：

```sh
git log --oneline -8
git revert 要撤回的提交编号
npm run check
npm run publish:github
```

有冲突时先解决并完成回退。不要用 `reset --hard` 加强制推送覆盖公开历史。只想撤下某篇内容，也可将它改为草稿，保存、提交、重新发布。

## 12. 数据、方案与代码位置

| 位置 | 作用 |
| --- | --- |
| `PAPERBULLET.code-workspace` | VS Code 工作区入口 |
| `.vscode/tasks.json` | 后台、预览、检查、发布任务 |
| `content/editorial.json` | 文章、播客、分类源数据，包含草稿 |
| `src/content/published.json` | 自动生成的公开列表与索引 |
| `public/archive-articles/` | 自动生成、按文章加载的公开正文 |
| `shared/editorial-defaults.mjs` | 旧数据的默认栏目定义 |
| `admin/` | 后台界面、连续编辑器和样式 |
| `shared/rich-text.mjs` | 连续编辑文档与原有段落数据的转换 |
| `shared/article-editing.mjs` | 分别保存各语言的正文与序言位置 |
| `server/local-admin.mjs` | 本地登录、保存、上传服务 |
| `server/content.mjs` | 数据校验、冲突保护、公开数据生成 |
| `src/ContentBlocks.jsx` | 正文格式与图片显示 |
| `public/uploads/` | 上传图片 |
| `scripts/publish-github.mjs` | 需要终端确认的手动发布脚本 |
| `.github/workflows/deploy.yml` | GitHub Pages 构建部署 |
| `.local-admin/` | 本机登录资料，不提交或发布 |

`content/editorial.json` 会随 Git 提交。公开仓库里的草稿虽然不显示在网站，仍能从源码看到。「草稿」不是保密权限；需要保密的内容先存仓库外，或另行使用私有仓库存储。

以下是文章字段示例，**不要用示例覆盖整份数据文件**：

```json
{
  "id": "example-review",
  "number": "006",
  "title": "文章主标题",
  "subtitle": "副标题或摘要",
  "author": "作者署名",
  "category": "影评",
  "collection": "columns/zige",
  "status": "draft",
  "publishedAt": "2026-11-21T15:30",
  "cover": "",
  "titleStyle": { "fontSize": 40, "bold": false, "italic": false, "align": "left" },
  "subtitleStyle": { "fontSize": 18, "italic": true },
  "coverStyle": { "width": 80, "maxHeight": 360, "align": "center" },
  "blocks": [
    { "type": "paragraph", "text": "第一段文字。", "fontSize": 18, "bold": false, "italic": false, "align": "left" }
  ]
}
```

连续编辑器仍使用经过校验的段落数据保存；局部格式使用可选的 `runs` 字段，每段的 `text` 保留完整纯文字，便于目录、搜索与旧数据兼容，不保存任意网页 HTML。一般无需手工修改这些字段。

可在 VS Code 直接编辑源数据，但应先处理后台未保存内容；编辑后运行 `npm run content:publish` 并重新载入后台。不要直接改生成文件，下一次保存或构建会重新生成它。
