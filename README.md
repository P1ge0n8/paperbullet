# PAPERBULLET · 锵稿

可在 VS Code 编辑、通过 GitHub 管理的静态网站，附带仅本机运行的内容后台。

## 启动

使用 Node.js 22.12+，在 VS Code 打开整个项目文件夹：

```sh
npm install
npm run admin
```

打开 http://127.0.0.1:4181/admin/ 。首次访问设置管理员账号和密码（至少 12 字符）。前台预览为 http://127.0.0.1:4181/ 。后台只监听本机，不作为在线管理服务部署。

只查看前台也可使用 `npm run dev`。后台运行时前台预览与后台共用 4181 端口。

## 编辑内容

- **文章**：新建、编辑、删除，选择专栏作者或影展、作者署名、分类、导语、封面、草稿或已发布状态。正文采用分段编辑：正文、二/三级标题、引用、图片和外链；每段可调字号、粗体、斜体及对齐，段落可上移/下移。点击「预览排版」检查效果。
- **发布时间**：文章和播客均支持日期及分钟，前台原样显示填写的当地时间。不自动换算时区，不定时发布。文章的公开与否由状态控制；列表顺序由上移/下移控制。
- **播客**：可更改标题、封面、跳转链接、发布时间、时长、试听标记和排列顺序。
- **图片库**：支持 PNG / JPG / WebP / GIF，最大 10 MB。上传图片保存到 `public/uploads/`，在封面或正文中选用。为避免误删正在使用的图片，后台不提供图片删除；确认无引用后可在 VS Code 中删除文件。
- **保存**：「保存全部修改」会保存文章与播客的所有修改。前台刷新后可见已发布内容。未保存时关闭页面有提示。同一份内容在别处已修改时，后台拒绝覆盖，先重新载入再合并。
- **示例文章**：现有 3 篇网站排版示例仍独立保留，不属于正式作者作品，也不会出现在正式文章编辑列表中。正式文章另行新建。

## VS Code 与 GitHub 更新

1. 后台编辑后，点击「保存全部修改」。
2. 终端执行 `npm run build`，检查网站可正常生成。
3. 在 VS Code 左侧「源代码管理」中查看修改，暂存需要更新的文件，填写提交说明并提交。
4. 点击「同步更改」或推送到已有的 GitHub 仓库。

项目当前 remote 为已有的 `P1ge0n8/paperbullet`。后台不会替你自动提交、推送或部署。GitHub 是否更新公开网站取决于原有发布配置。没有设置发布流程时，推送只更新仓库。

主要内容文件：

- `content/editorial.json`：后台的文章与播客源内容，包括草稿。
- `src/content/published.json`：保存和打包时生成的公开内容，不含草稿。
- `public/uploads/`：新上传图片。
- `public/assets/`：现有网站资产。
- `src/`：网站代码；`admin/`：本地后台界面；`server/`：本地登录及保存逻辑。

可在 VS Code 直接编辑 `content/editorial.json`，然后重新载入后台；构建会校验并生成公开内容。不要手动改生成的 `src/content/published.json`。

`content/editorial.json` 会随 Git 提交；如果 GitHub 仓库公开，草稿在仓库里也可被看到（但不会出现在网站）。需要保密的草稿应使用私有仓库。

## 登录资料与换电脑

账号密码的加盐散列保存在 `.local-admin/account.json`，该目录已经被 Git 忽略，不会随正常提交上传。新电脑克隆项目后需重新设置本机账号。登录会话持续 8 小时，重启后台后重新登录。

忘记本机密码：停止后台，把 `.local-admin/account.json` 移到项目外作备份，再启动后台设置新账号。文章和图片不会受影响。不要把该文件或测试目录强制加入 Git。

## 验证

```sh
npm run build
node --test tests/admin.test.mjs tests/content.test.mjs tests/sites-worker.test.mjs
```

后台测试使用独立临时目录，不改动真实账号或内容。管理页面只由本地开发服务提供，不包含在 `dist/client` 的公开站点构建中。
